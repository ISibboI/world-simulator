# 2026-11-16

## Session 1: runtime optimisations (continued)

User asked for the hidden-crust fix first, then a comparison of alternative hash maps and an
array.

### Hidden crust tracking in the matching (commit 390dcc4)

The perf profile had `update_crust_cells` at 14%. The suspected cause (scanning every local
vertex for hidden samples) was wrong: that scan is sequential and cheap. Annotation showed the
cost was (a) random reads of `crust[lookup_cache[cell]]` for every searched cell including the
three empty rings, and (b) long `nearest_from` walks for hidden samples, each starting from the
previous hidden sample's cell. Fix: `match_plates` returns only the matched (cell, local) pairs;
each plate keeps `TrackedCrust { cells, samples: Vec<(local, nearby cell)> }`, and hidden samples
start their walk from their stored cell. Crust is only created in filled cells or in
splits/merges (which reset the tracking; the degenerate "all crust destroyed" restart resets it
too). 200 Myr seed 0: −5.4% instructions, −12% cycles, identical output; `--verify-matching` at
full resolution: 0 mismatches.

### Hash maps vs arrays

The tectonics now use `HashMap`/`HashSet` aliases (in `tectonics/mod.rs`) with one `Hasher`
type. 200 Myr, seed 0, `perf stat` (all outputs identical to before):

| Variant | Instructions | Cycles | Time |
|---|---|---|---|
| std SipHash | 340.3 G | 240.2 G | 63.1 s |
| rustc-hash (Fx) | 290.4 G | 224.6 G | 59.0 s |
| foldhash (random / fixed) | 290.4 / 290.8 G | 224.1 / 221.4 G | 58.9 / 58.1 s |
| ahash | 292.5 G | 222.6 G | 59.1 s |
| arrays for `Ownership` maps + std | 278.8 G | 218.6 G | 57.9 s |
| **arrays + Fx (chosen)** | 277.2 G | 213.6 G | 57.2 s |

Run-to-run noise is a few percent in cycles; the fast hashers are tied. **User decision:
arrays + Fx.** The per-sample maps (visible/consumed samples in `resolve_ownership` per substep,
crustal flow and surface changes per step) use dense arrays indexed by
`plate × cells + local` (`sample_index`); the small plate-pair maps use `rustc-hash`, which is
also deterministic (std's was randomly seeded per run).

Cumulative: the default 500 Myr run went 414 s → ~170 s (incremental matching) and a further
~25% fewer cycles since.
