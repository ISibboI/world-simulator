# 2026-11-16

## Session 1: runtime optimisations (continued)

User asked for the hidden-crust fix first, then a comparison of alternative hash maps and an
array.

### Hidden crust tracking in the matching (commit 390dcc4)

The perf profile had `update_crust_cells` at 14%. The suspected cause (scanning every local
vertex for hidden samples) was wrong: that scan is sequential and cheap. Annotation showed the
cost was (a) random reads of `crust[lookup_cache[cell]]` for every searched cell including the
three empty rings, and (b) long `nearest_from` walks for hidden samples, each starting from the
previous hidden sample's cell. Fix: `match_plates` returns only the matched (cell, local) pairs;
each plate keeps `TrackedCrust { cells, samples: Vec<(local, nearby cell)> }`, and hidden samples
start their walk from their stored cell. Crust is only created in filled cells or in
splits/merges (which reset the tracking; the degenerate "all crust destroyed" restart resets it
too). 200 Myr seed 0: −5.4% instructions, −12% cycles, identical output; `--verify-matching` at
full resolution: 0 mismatches.

### Hash maps vs arrays

The tectonics now use `HashMap`/`HashSet` aliases (in `tectonics/mod.rs`) with one `Hasher`
type. 200 Myr, seed 0, `perf stat` (all outputs identical to before):

| Variant | Instructions | Cycles | Time |
|---|---|---|---|
| std SipHash | 340.3 G | 240.2 G | 63.1 s |
| rustc-hash (Fx) | 290.4 G | 224.6 G | 59.0 s |
| foldhash (random / fixed) | 290.4 / 290.8 G | 224.1 / 221.4 G | 58.9 / 58.1 s |
| ahash | 292.5 G | 222.6 G | 59.1 s |
| arrays for `Ownership` maps + std | 278.8 G | 218.6 G | 57.9 s |
| **arrays + Fx (chosen)** | 277.2 G | 213.6 G | 57.2 s |

Run-to-run noise is a few percent in cycles; the fast hashers are tied. **User decision:
arrays + Fx.** The per-sample maps (visible/consumed samples in `resolve_ownership` per substep,
crustal flow and surface changes per step) use dense arrays indexed by
`plate × cells + local` (`sample_index`); the small plate-pair maps use `rustc-hash`, which is
also deterministic (std's was randomly seeded per run).

Cumulative: the default 500 Myr run went 414 s → ~170 s (incremental matching) and a further
~25% fewer cycles since.

## Session 2: further runtime optimisations (continuation of an aborted agent)

An earlier session's agent was aborted while benchmarking a set of optimisations from
`research/profiling-2026-11-15.md` ("cheaper ledger, birth time instead of age, cached boundary
list" and two small ones). This session reconstructed the uncommitted work, verified and
committed it.

Changes:

1. **Ledger checked only when reported**: `ledger::plates_mass` (a sum over all samples) no
   longer runs around every operation; operations return the mass change they caused (crustal
   flow, additions), dead plates record their own mass, and `MassLedger::checked` compares with
   the total only for statistics. The residual telescopes, so the result is the same. The ledger
   test now checks closure after every step and every surface change.
2. **Formation time instead of age**: `Crust::birth` (simulated Myr; negative for crust older
   than the run), `Crust::age(time)`; no aging pass over all samples every substep. Elevation and
   buoyancy take the time.
3. **Boundary list reused** within a step: `boundary_cells()` is computed once for slab lengths,
   suturing and subduction rates, recomputed only if the plate configuration changed
   (`topology_changes`, counted in splits and removals) or a slab appeared/disappeared.
4. **`RingScratch`** for `opens_away` in the gap filling (stamped visited array instead of
   `Vec::contains` and per-call allocations).
5. **Mantle flow without trigonometry**: `cos θ`, `sin θ` from dot/cross products,
   `radial_speed_per_sine`.

Verification:

- A scratch variant with the old age accumulation (`age += dt` per substep, emulated through the
  new field) and the old mantle code is **bit-identical** to HEAD (logs incl. ledger and all PNGs)
  over 200 Myr seed 0 and 500 Myr seeds 0–2, so changes 1, 3 and 4 are exact.
- Changes 2 and 5 change floating-point rounding (`time − birth` vs. summed `dt`), so runs diverge
  chaotically. 500 Myr, seeds 0–2, HEAD vs new: no systematic shift (ocean age 39/54/67 vs.
  48/48/60 Myr, continental 24–30% vs. 26–33%, land mean 1.3–1.9 vs. 1.2–2.1 km). New seed 2
  ends colder (6.3 °C, 21% frozen) than any HEAD run; within ice–albedo sensitivity.
- 200 Myr seed 0, `perf stat` (aborted agent's measurements): 277 G → 233 G instructions,
  214 G → 141 G cycles (−34%), 56.6 s → 37.7 s.
- fmt, clippy (all targets/features), tests, doc with warnings denied; fixed a doc link to the
  now test-only `radial_speed_factor`.
